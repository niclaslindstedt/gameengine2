## Notes for the build

- **Character movement's state (M28c).** `engine/move`'s `MoveState` carries `ground_solid` (the
  id of the solid a body stands on, 0 for none), `ground_vel` (that solid's velocity; a standing
  body's own velocity is relative to it) and `on_ladder`. A predicting client keeps all three per
  predicted tick and restores them before a replay, or a replay from a moving platform or a ladder
  diverges from the server's step.
- **Moving solids are part of the predicted world.** A replay matches the server only when every
  solid it touches stands where it stood on the server at that tick, so movers' positions go in the
  snapshot and the client steps them on the same clock as its own body. In the predicted world a
  mover is an entity with no input (`Predicted::stepped` false): it is moved only by contacts, so a
  mover with its own path needs the game's step for it in the schema (not built: no game has one
  yet). The three `MoveState` fields go in the game's schema as fields like any other, so the
  replay restores them with the rest of the state.
