The `gpu` lane is drawn from each frame's pass timestamps, placed from the CPU's submit time,
because the GPU's clock and the CPU's have no known offset. On the container's software adapter
the timestamps measure the rasterizer's CPU threads, which the OS sampler already shows as
unmarked threads, so this is honest there. On a hardware adapter the lane's start is late by
the queue's wait.
