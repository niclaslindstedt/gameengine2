Status: in progress

M17m1 is built. `engine/net/stress.hpp` holds four pressure tests over the fake-traffic session:

- ramps that bisect each link knob to its breaking point;
- eight chaos scripts, with reconnects;
- a soak that holds memory flat;
- a fuzzer beside an honest session.

`ge net stress` runs them from the command line, and the `net-stress`, `net-chaos` and `net-fuzz`
labs chart them. The traffic plan gained the chaos steps, the reconnect tries, a per-tick hook and
summed latencies. A session without them keeps its digest, so `net-link`'s smoke digest is
unchanged.

Measured, against the done-when cell:

- **Breaking points.** `ge net stress` names each knob's breaking point for a mix. For racing with
  eight clients from broadband: 14% loss, bursts of 56 drops, 250 ms of latency or jitter, and
  54 kbit/s.
- **Soak.** An hour at 32 clients takes 12 s in the release build. Memory held flat at 34 MB. The
  packet sequence and the reliable ids each wrapped twice, with every reliable message delivered.
- **Fuzz.** A million fuzzed datagrams went through the parser and the node under the debug
  build's ASan and UBSan. The first run found one undefined shift: `place_sequence` shifted the
  ack bits by the sequence's jump, which a forged sequence or a long outage can push past 64. It
  is fixed, `tests/net_connection_test.cpp` holds it, and the rerun is clean. The honest session
  never noticed.
- **Chaos.** Every chaos script ends with each client reconnected or cleanly timed out.

Left for M17m2:

- **Load.** Many sessions in one host process, with the host's step timed per session.
- **Bots.** A game's bots as clients across many simulated servers.
- **Rebinding.** Keep a connection when a NAT rebinds a client's port: today the client
  reconnects after the timeout. The new address would be taken on a payload that the session key
  authenticates, so this waits on M17i's AEAD.
