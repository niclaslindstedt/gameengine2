`engine/net/lockstep.hpp` steps a session of seats in a mesh. In lockstep mode it runs turns with
an input delay and waits for every seat's input. In rollback mode it predicts missing inputs, loads
the state from before a misprediction and runs every step since again. Each peer compares every
seat's step digests, so a desync is named by its step. `engine/net/lockstep_trial.hpp` holds a
strategy game and a fighting game; the `net-lockstep` lab runs both under each preset.

Measured: four strategy peers agree under every preset (`tests/net_lockstep_test.cpp`), and a desync
planted on step 600 is named step 600 on every preset, seen 17 ms (lan) to 233 ms (awful) later.
